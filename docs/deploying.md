# Deploying

The app is one Cloudflare Worker, `odd-reveal`, configured in [`wrangler.jsonc`](../wrangler.jsonc). It serves the static client from `public/` through Workers Static Assets and runs Phones mode rooms in a Durable Object.

## Deploy

```sh
npm ci
npm test          # deploy only from a green suite
npm run deploy    # wrangler deploy
```

Wrangler needs either `wrangler login` or `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` in the environment. There is no CI workflow; deploys are run by hand.

The custom domain (https://oddcard.hatethespurs.com) is attached to the Worker in Cloudflare, not in `wrangler.jsonc`. The config keeps the `workers.dev` route on and preview URLs off. `test/deploy-workersdev.test.js` pins both values, so change the test with the config.

## Bindings

| Binding  | Kind                   | Use |
|----------|------------------------|-----|
| `ROOM`   | Durable Object (`Room`) | One object per room code |
| `ASSETS` | Static Assets          | Files in `public/` |
| `AI`     | Workers AI             | "Ask a rule" endpoint, off by default |
| `AI_MODE`| var                    | `"dark"`: no model calls. Only `"on"` calls the model |

`test/deploy-bindings.test.js` checks that every binding in `wrangler.jsonc` also reaches the single-file build's upload metadata.

## Durable Object migration

`Room` was created with migration tag `v1` as a SQLite-backed class (`new_sqlite_classes`). Keep that entry as it is. A class cannot switch between SQLite and key-value storage after it has been deployed, and editing or removing an applied migration makes the deploy fail. Any later change to Durable Object classes (rename, delete, new class) needs a new migration with a new tag appended after `v1`.

Rooms clean themselves up: each one sets an alarm on creation and deletes its storage 12 hours later.

## Service worker

`public/sw.js` precaches every file in `public/`, and its `VERSION` is a content hash of those files. The file is generated by a PWA tool kept outside this repo. When you add, remove or change a public file, update the precache list and `VERSION` so installed copies pick up the change. `test/files.test.js` fails if a public file is missing from the precache list.

## Rules index

`src/rules-index.js` is generated from `public/js/faq.js`. After editing the FAQ, run `node scripts/build-rules-index.mjs`. A test fails if the index is out of date.

## Single-file build (optional)

`node scripts/build-embedded.mjs` writes `dist-embedded/worker.js`: the Worker with every file in `public/` inlined, bundled with esbuild. It is for deploying through the Cloudflare API without the static assets upload step. `npm run deploy` is the normal path. `dist-embedded/` is not committed.
